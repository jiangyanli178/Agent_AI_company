## 一、数据库专用账号（你问的那个）

### 1.1 这是什么意思

MySQL 里每个账号有两层限制：

| 限制 | 例子 | 含义 |
|---|---|---|
| **能从哪里连**（host） | `root@localhost` | 只能在这台机器上连，外面连不进来 |
| **能干什么**（权限） | `SELECT`、`DROP` | 能查数据，还是能删表 |

`root` 是**超级管理员**：能看所有数据库、能删库、能改别人权限。

### 1.2 为什么不能给程序用 root

假设你的代码里有一个 SQL 注入漏洞（比如某个参数没做转义），
攻击者就能让数据库执行他写的 SQL。

| 程序用的账号 | 攻击者能做到 |
|---|---|
| **root** | `DROP TABLE users;` 把用户表删了；`DROP DATABASE quant_shop;` 整个库没了；甚至新建一个管理员账号留后门 |
| **专用账号** | 只能增删改查 `quant_shop` 里的数据行。**表结构删不掉，库删不掉，别的库碰不到** |

**一句话：专用账号是为了"即使被攻破，损失也有上限"。**

### 1.3 怎么做（上线时执行一次）

```sql
-- ① 新建一个专用账号，只允许本机连接
CREATE USER 'quant'@'localhost' IDENTIFIED BY '换成一个足够长的随机密码';

-- ② 只给 quant_shop 这个库的增删改查权限
GRANT SELECT, INSERT, UPDATE, DELETE ON quant_shop.* TO 'quant'@'localhost';

-- ③ 生效
FLUSH PRIVILEGES;
```

**注意第二条里没有什么**：
- 没有 `DROP`（不能删表）
- 没有 `TRUNCATE`（不能清空表）
- 没有 `CREATE`（不能建表）
- 没有 `GRANT`（不能给别人授权）
- 没有 `*.*`（不能碰其它数据库）

然后把 `backend/.env` 里的账号换掉：

```ini
DB_USER=quant
DB_PASSWORD=那个随机密码
```

改完重启后端，确认 `/api/health` 里 `db_connected` 还是 `true`。

### 1.4 什么时候不用做

**演示阶段用内网穿透时可以暂缓**，因为我已经查过你的 MySQL：
`root@localhost` 意味着外部根本无法用 root 登录，风险已经很低。

**但如果哪天把 MySQL 也暴露到公网，或者换成云服务器，这一步就是必须的。**
