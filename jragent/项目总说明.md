## 1. 总体架构

`bis` 工作区包含三个相互独立、按需协作的子系统：

```
jragent/
├── agents/
│   ├── mimo-social-agent/  刷视频 · 抓评论 · 回复（抖音/B站）+ 每日策略回撤流水线
│   └── mimo-zxg-agent/     腾讯自选股运营：财经汇总agent → 校验agent → 自动发帖
├── backend/
│   └── opc_quant_studio/   量化策略研究/回撤系统（回测引擎 + 11 Agent + 合规闸门）
├── studio/
│   ├── context_hub/        量化工作室卷宗（00-charter ~ 09，单一事实来源）
│   └── outputs/            回测交付物（drawdown.png / equity_curve.png / report.md）
├── frontend/               策略体检所 + 量化工作室同一网站前端（Vue3，工作室页面在 /studio/）
├── hub/                    策略体检所公司大脑卷宗（文档版）
└── docs/agent-architecture.md  量化工作室 11 Agent 架构详版（另行文档）
```

三大子系统的角色：

| 子系统 | 角色 | 控制台 | 与其它系统的关系 |
|---|---|---|---|
| mimo-social-agent | 社交互动执行者：刷视频、抓评论、人设化回复 | http://127.0.0.1:8765 | 流水线调用 opc_quant_studio 做策略回撤 |
| mimo-zxg-agent | 财经内容运营：双 Agent 汇总+校验后发帖到腾讯自选股 | http://127.0.0.1:8766 | 独立运行，不依赖其它子系统 |
| opc_quant_studio | 回撤/回测能力提供者 | —（CLI/被 import 调用） | 被 mimo-social-agent 的策略流水线跨项目调用 |

**隔离原则**：两个社交项目目录、端口（8765/8766）、浏览器登录态（各自 `.browser-profile/`）完全隔离，互不干扰；回撤系统只以 Python 包形式被 import，不发任何社交内容。

## 2. mimo-social-agent：刷视频社交互动

### 2.1 功能总览

浏览器自动化（Playwright + Chrome）完成「刷视频 → 抓评论 → 筛选 → 回复」闭环，支持抖音与 B 站两个平台。

| 功能 | 说明 |
|---|---|
| 登录门控 | 未登录只显示登录页；`login` 打开浏览器自动填账号密码（滑块/验证码人工完成）；`auth-status` 无头检测登录态；`logout` 清 Cookie 退出 |
| 刷视频（browse） | 按主题搜索词收集视频列表（标题+链接），可点选视频进入抓评论 |
| 抓评论（scan） | 抓取指定视频评论（用户/内容/点赞），支持**评论关键词筛选**（逗号分隔，留空=不过滤抓全部） |
| 回复（reply） | 对候选评论生成人设化回复并提交；**只提交一次，失败不重试**；同一条评论不重复回复 |
| 策略回撤流水线（pipeline） | 每日定时：抓视频+评论 → 识别策略内容 → 调回撤系统 → 模板只回「收益+最大回撤」给该用户（详见第 5 节） |
| 提示词模板 | `prompts` 三模板（回复生成/评论筛选/关键词扩展），界面可一键生成、复制、恢复默认 |
| 只抓取模式 | 勾选「只抓取不回复」后 scan 仅采集不生成回复 |

### 2.2 CLI 子命令（bot.py）

```powershell
python bot.py [--platform douyin|bilibili] [--headless] <子命令>
```

| 子命令 | 作用 |
|---|---|
| `browse` | 刷视频，输出视频链接列表 |
| `scan` | 抓取视频评论并按关键词筛选，候选存入 state |
| `reply` | 按 `--index`/`--cid` 回复候选评论 |
| `status` | 查看限额与最近扫描状态 |
| `login` / `auth-status` / `logout` | 登录 / 检测登录态 / 清除登录 Cookie |
| `pipeline` | 每日策略回撤流水线（`--dry-run` 只回测不实发、`--search`、`--max-videos`、`--max-replies`） |

注意：`--headless` 是**全局参数**，必须放在子命令之前，例如 `python bot.py --headless pipeline --dry-run`。

### 2.3 config.json 配置说明

| 段 | 字段 | 说明 |
|---|---|---|
| 顶层 | `platform` | `douyin` 或 `bilibili` |
| `account` | `username` / `password` | 登录时自动填充（滑块人工） |
| `topic` / `keywords` | 主题与评论筛选关键词 | browse 搜索词与 scan 筛选默认值 |
| `persona` / `reply_rules` | 人设、回复风格、违禁词 `avoid` | 回复生成约束，命中违禁词直接拦截 |
| `limits` | `max_replies_per_run` / `max_replies_per_day` / `min_interval_seconds` | 每次/每日回复上限、最小回复间隔 |
| `skip` | `users` / `min_comment_likes` | 跳过指定用户、低赞评论 |
| `pipeline` | `enabled` / `time` / `search` / `max_videos` / `max_comments_per_video` / `max_replies_per_run` | 流水线定时与采集上限 |
| `pipeline` | `period` / `default_symbol` / `strategy_keywords` | 回测周期（2y）、缺省标的（600519）、策略识别关键词（均线/金叉/突破/止损/回测/量化等） |
| `pipeline` | `reply_template` | 回复模板，占位符：`{total_return} {max_drawdown} {annualized_return} {sharpe} {win_rate} {symbol} {idea}` |
| `prompts` | `reply_generation` / `comment_filter` / `keyword_expansion` | 三份提示词模板 |

默认回复模板（只含回撤和收益，附合规提示）：

```
【回测参考】收益 {total_return}｜最大回撤 {max_drawdown}（历史回测不代表未来，不构成投资建议）
```

### 2.4 策略回撤流水线（pipeline）工作流

1. **一次浏览器会话**内完成全流程：`collect_videos` 按搜索词刷视频 → 每个视频 `fetch_comments` 截至 `max_comments_per_video`。
2. **策略识别**：视频标题+评论文本命中 `strategy_keywords` 任一词即视为策略相关内容；提取 6 位 A 股代码（无代码用 `default_symbol`），并从原句提取策略描述。
3. **回撤回测**：跨项目调用 opc_quant_studio（详见 5.3），产出收益/最大回撤等指标。
4. **模板回复**：渲染 `reply_template`，经软安全闸门（违禁词/限额/间隔/去重）后回复到该用户评论下。
5. 任何一步失败（无代码/回测失败/闸门拦截）只记入结果 `skipped`，不中断整体流程。

## 3. mimo-zxg-agent：腾讯自选股运营

### 3.1 双 Agent 流水线

两个专职 Agent 以「简报文件」接力，职责严格分离：

```
Research（汇总 Agent）──► reports/YYYY-MM-DD-brief.md ──► Fact-Check（校验 Agent）
                                                              │
                                          reports/YYYY-MM-DD-verified.md（校验稿）
                                          reports/YYYY-MM-DD-publish.txt（发布终稿）
                                                              │
                                                  bot.py zxg-publish（浏览器发帖）
                                                              ▼
                                                     腾讯自选股社区（gu.qq.com）
```

| Agent | 定义文件 | 职责 | 约束 |
|---|---|---|---|
| 财经信息汇总（Research） | `zxg-research.md` | 访问 `research.sources` 财经网站（路透/彭博/CNBC/新浪财经/东方财富/财联社/第一财经/政府/央行/统计局），筛选「对股市有影响且对投资者有用」的信息，产出带来源引用的简报（`*-brief.md`） | 不做真实性判定、不发帖；单源失败跳过，至少覆盖 3 个源；最多 `max_items` 条、只收 `lookback_hours` 时间窗内 |
| 真实性校验（Fact-Check） | `zxg-factcheck.md` | 逐条核实简报（多源交叉印证、官方渠道、数字与时间核对），剔除不实/存疑，产出校验稿与发布终稿，并调用 bot.py 发布 | **未经校验通过的内容一律不得发布**；不凭空编造 |

两份 md 为 Agent 定义（front-matter 声明权限：bash/webfetch 允许、edit 禁止），可被智能体直接加载执行。

### 3.2 发布执行（bot.py）

| 子命令 | 作用 |
|---|---|
| `zxg-login` | 打开浏览器登录腾讯自选股，登录态存入 `.browser-profile/` |
| `zxg-publish` | 发布一条帖子（`--text` 指定内容 / `--file` 读发布终稿 / `--dry-run` 试发）；**单次提交不重试**；未指定内容时从 `zxg.content_pool` 取备用文案 |
| `zxg-logout` | 清除登录 Cookie |
| `auth-status` | 无头检测登录态 |

发布内容经 `zxg.avoid` 违禁词过滤（稳赚/必涨/荐股/内幕消息等），每日最多 `zxg.max_per_day` 条（默认 3）。

### 3.3 config.json 配置说明

| 段 | 字段 | 说明 |
|---|---|---|
| `zxg` | `publish_url` / `max_per_day` / `avoid` / `content_pool` | 发布入口、每日上限、违禁词、备用文案池 |
| `zxg.daily` | `enabled` / `time` | 每日定时发帖开关与时间（默认 09:00） |
| `research` | `sources` / `max_items` / `lookback_hours` | 信息源列表（10 个）、简报条数上限（8）、时间窗（24h） |
| `prompts` | `research` / `factcheck` / `post_generation` | 汇总 / 校验 / 成文三段提示词 |

### 3.4 webui（8766）

- 路由：`/api/config`（保存配置）、`/api/zxg-publish`（发帖）、`/api/zxg-login`、`/api/zxg-logout`，`reports/` 简报列表展示（brief/verified/publish 三类）。
- `daily_zxg_scheduler()`：每日定时发帖（见第 6 节）。

## 4. opc_quant_studio：量化策略回撤系统

三层架构（**执行层 11 个专职 Agent + 编排层 COO + 中枢层 Context Hub 与 9 道人工闸门**）的完整细节见 [agent-architecture.md](./agent-architecture.md)，此处只列被外部调用的接口。

| 模块 | 对外接口 | 说明 |
|---|---|---|
| `agents.py` | `StrategyTranslator.translate(idea)` | 自然语言策略 → `StrategySpec`（识别「突破/均线金叉/死叉、N/M 周期、止损X%」，默认 10/40 止损 5%） |
| `backtest.py` | `run_backtest(spec, snap)` | 返回 `BacktestResult.metrics`：`total_return / annualized_return / max_drawdown / sharpe / win_rate / n_trades`（含交易成本、执行滞后≥1 根K线、风控双审计） |
| `data_manager.py` | `fetch_cn / fetch_baostock / fetch_public / synthetic_ohlcv` | 数据降级链：akshare → baostock → yfinance → 合成数据（合成**必须披露**） |
| `context_hub.py` | `ContextHub(root)` | 文件型卷宗 00-09，`append/write/read/log/save_backtest_asset`，全部留痕可回滚 |
| `compliance.py` | `BANNED_WORDS / scan / ensure_disclaimers` | 违禁词扫描、免责声明强制附加 |

### 5.2 webui → bot.py 的统一调度模式

两个 webui 采用相同范式：

1. webui 只做**配置管理 + 触发 + 结果展示**，所有浏览器动作都由 `run_bot(args)` 以**子进程**调用 `bot.py` 对应子命令完成（互不污染、崩溃隔离）。
2. `run_bot` 解析 bot.py stdout 的**最后一段 JSON** 作为结构化结果返回给页面。
3. `bot.py` 每次运行都是单次任务：起浏览器（复用 `.browser-profile/` 登录态）→ 执行 → 输出 JSON → 退出。

### 5.3 策略回撤流水线的跨项目调用链

`strategy_pipeline.py` 是两个世界的桥：

1. 启动时把 `bis/` 注入 `sys.path`，直接 `import opc_quant_studio`（agents / backtest / data_manager / context_hub）。
2. 流程：`bot.get_platform()` 抓视频+评论 → `is_strategy_related()` 关键词识别 → `extract_symbol()/extract_idea()` 提取标的与策略描述 → `StrategyTranslator.translate()` → `collect_snapshot()`（数据降级链，失败记 `fallback_errors`）→ `run_backtest()` → `render_reply()` 模板渲染。
3. 回复前过**软安全闸门** `soft_check_reply()`（镜像 bot 的 die 版闸门但返回 `(ok, reason)` 不退出），随后按最小间隔等待并 `post_reply()` 回到原评论下。
4. 全程在 `pipeline_hub/` 卷宗留痕（审计可回滚）。

**隔离性**：mimo-zxg-agent 与刷视频/回撤流水线完全独立（不同目录、端口、浏览器 profile），互不调用。

## 6. 每日定时调度机制

两个 webui 内置同款 daemon 调度线程（30 秒轮询）：

| 项目 | 调度器 | 配置开关 | 触发条件 | 动作 |
|---|---|---|---|---|
| mimo-social-agent | `daily_pipeline_scheduler()` | `pipeline.enabled` + `pipeline.time`（HH:MM） | ① 开关开 ② 当前时刻等于设定时间 ③ 今天未触发过（`fired_date` 当日去重） | `run_bot(["--headless", "pipeline"])`（全流程含回复） |
| mimo-zxg-agent | `daily_zxg_scheduler()` | `zxg.daily.enabled` + `zxg.daily.time` | 同上 | `run_bot(["--headless", "zxg-publish"])`（从 content_pool/终稿发帖） |

要点：

- **前提**：对应 webui 进程必须保持运行（调度线程随 webui 启动）。
- 精确到分钟匹配（`%H:%M`），错过时间点当天不会补跑；`fired_date` 保证一天只触发一次。
- 改 `config.json` 的时间/开关后**无需重启**（每轮实时读配置）；改 `webui.py`/`bot.py` 代码才需重启 webui；改 `webui.html` 刷新页面即生效。

## 7. 状态、限额与去重

`state.json`（mimo-social-agent，脚本自动维护）：

| 字段 | 作用 |
|---|---|
| `replied` | 已回复评论 cid → 时间/内容/状态，保证同一条评论不重复回复 |
| `daily` | 日期 → 当日回复计数，配合 `max_replies_per_day` 限额 |
| `last_reply_ts` | 上次回复时间戳，保证 `min_interval_seconds` 最小间隔 |
| `last_scan` | 最近一次 scan 的候选列表（reply 按 index/cid 定位） |

mimo-zxg-agent 侧对应 `zxg.max_per_day` 每日发帖上限；两个项目的回复/发帖都**只提交一次，失败不重试**。

## 8. 合规红线汇总

| 红线 | 落地 |
|---|---|
| 不荐股、不代客理财 | 回复模板只给历史回测数据，不含买卖建议；Agent 永不碰资金与交易 |
| 不承诺收益 | 违禁词表拦截（保本/稳赚/必涨/荐股/翻倍/内幕消息等），社交回复与发帖双重过滤 |
| 必带风险揭示 | 回复模板强制含「历史回测不代表未来，不构成投资建议」；发帖终稿附风险提示 |
| 业绩不造假 | 回测只用真实公开数据（akshare/baostock/yfinance），合成数据必须披露 |
| 全部留痕 | Context Hub 卷宗 + `pipeline_hub/` + `state.json`，可审计可回滚 |

### 9.3 开启每日定时

- **策略回撤流水线**：webui 8765「每日策略回撤流水线」区勾选「每日定时」+ 设时间 → 保存配置；建议先勾「干跑」试运行一轮。
- **自选股发帖**：webui 8766 配置 `zxg.daily.enabled = true` 并设 `time`（或直接改 config.json）。

### 9.4 注意事项

- `--headless` 是全局参数，必须放在子命令**前**（`python bot.py --headless pipeline`，不是 `pipeline --headless`）。
- webui 端口**独占**（`allow_reuse_address = False`）：重启前先关旧进程，否则新实例起不来（防止多实例抢端口导致 404）。
- 首次使用需先 `login` / `zxg-login` 完成登录（滑块/验证码人工），登录态存于各自 `.browser-profile/`。
- 回测数据源不可达时自动降级，最终兜底为合成数据并在结果中标注 `synthetic`，此类结果仅作演示。
