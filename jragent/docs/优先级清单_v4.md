# 优先级清单 · v4
## 自由对话是主入口 · 数据截至 T-1 · AI 只在已有框架内改参数

> 本版修正了一个定位错误：自由对话不能砍。
> **"用户说人话，系统去找策略并验证"才是降低量化门槛**；表单选策略和聚宽没有区别。

---

## 一、产品定位：对话是主入口，表单是辅助

### 1.1 主流程长这样

```
用户：给我一个能用的策略
  ↓
MiMo 判断意图 → 调 search_strategies(difficulty=1)
  ↓ 拿到 3 个候选
MiMo：新手先从均线交叉开始，我帮你跑一下历史数据看看
  ↓ 调 run_backtest(ma_cross_5_20, 600519)
  ↓ 拿到真实结果
MiMo：这个策略过去三年收益 21%，但同期买入持有是 54%，其实跑输了。
      最大回撤 25.7%，意味着中间最难受的时候账户会缩水四分之一。
      有 4 次买入信号因为涨停根本成交不了。
      要不要我换一个思路，或者换个标的再试试？
  ↓
用户：那换个稳一点的
  ↓ 调 compare_strategies → 出对比卡片
```

**每一步都有真实产出物**，不是聊天聊完就没了。这是和"AI 聊天壳"的本质区别。

### 1.2 为什么必须用工具调用，而不是自己写意图分类

赛题明确提供 MiMo-V2.6-Pro 的**工具调用与长程任务**能力。用它意味着：

- 不用自己写"用户这句话是什么意思"的分类器（那个东西永远调不准）
- 模型自己决定调几次工具、按什么顺序调
- 这正好就是赛题要的"多智能体协作"，是得分点而不是额外工作

### 1.3 已实现：`services/agent_tools.py`

6 个工具已定义并自测通过：

| 工具 | 干什么 | 什么时候被调 |
|---|---|---|
| `search_strategies` | 检索策略库 | "给我一个策略""有没有稳点的" |
| `run_backtest` | 跑真实回测 | **推荐任何策略之前必须调** |
| `compare_strategies` | 多策略同台对比 | "哪个更好""怎么选" |
| `list_symbols` | 查标的 | "随便找一只" |
| `explain_concept` | 查知识库 | "什么是金叉""为什么会失效" |
| `suggest_params` | 在已有框架内调参 | "帮我优化一下" |

### 1.4 两条写死在代码里的约束

**约束一：AI 只输出「框架 + 参数」，绝不输出代码。**

策略永远跑在我们自己的 `backtest.py` 里，不跑 AI 写的代码。
这带来四个好处：**安全**（不用代码沙箱）、**可复现**（同一引擎）、**可部署**（同一套信号生成）、**省工时**（不用写代码解释器）。

**约束二：没跑回测就不许评价策略。**

这条写在 `SYSTEM_PROMPT` 里，同时工具描述里也写了"强制"。双保险。

## 二、数据策略：一律截至昨天（T-1）

### 2.1 规则

| 项 | 规则 |
|---|---|
| 数据更新 | 每个交易日 18:00 拉一次，只拉到**最近一个已收盘交易日** |
| 回测区间 | `end_date` 上限 = 数据库里最新有数据的那天 |
| 页面展示 | **必须显式写"数据截至 2026-11-05"**，否则用户以为能回测到今天 |
| 当日信号 | 不产生。盘中的数据不用 |
| 复权 | `stock_zh_a_hist(adjust="qfq")`，前复权 |

### 2.2 为什么这件事必须在 UI 上显式标注

用户看到"近一年收益 30%"，会默认是到昨天为止。
如果你的数据其实停在一周前，这就是误导。
**在回测结果页顶部放一行小字「数据截至 YYYY-MM-DD，T 日数据于收盘后次日更新」**，成本是一行字，省掉的是信任问题。

### 2.3 演示日的特殊处理

**不要指望现场能拉数据。** 提前一天把 30 只标的 5 年日线全部拉好入库，并 `mysqldump` 备份。
演示时数据库是只读的，回测纯本地计算，**断网也能演**。

## 三、部署：AI 在已有框架内帮你改，不写新代码

### 3.1 你说的"靠系统已有的框架修改"，这个判断非常对

它把一个本来做不完的功能，变成了可做的功能：

| 做法 | 工作量 | 风险 |
|---|---|---|
| AI 自由写策略代码 → 沙箱执行 | 10h+ | 任意代码执行，安全隐患大 |
| **AI 在 5 个已有框架内选参数** | **2h** | 无 |

### 3.2 落地流程

```
用户：帮我把这个策略部署了
  ↓
MiMo 调 suggest_params(goal="lower_drawdown")
  ↓ 返回 3 组参数 + 各自的回测结果 + 过拟合警告
MiMo：我把慢线从 20 调到 40，回撤从 24% 降到 18%，
      但交易次数从 23 次降到 10 次。这只是参数调整，
      换一只票结果可能完全不同，你要不要再验证一下？
  ↓
用户确认 → 写入 deployments（框架类型 + 参数 + 标的）
  ↓
每日 18:30 用同一个 backtest.py 算最新信号，写 signals 表
```

**关键：回测和部署用的是同一个 `run_backtest()`。** 不会出现"回测一套逻辑、实盘另一套逻辑"这种最常见的坑。

### 3.3 如果 24 小时里没时间做部署

降级为「**加入观察列表**」：只存配置，不跑调度。
页面上展示预生成的历史信号，并明确标注"以下为历史回测信号"。
**保留产品形态，但不写调度逻辑**，这样最多再省 2 小时。

## 五、对话的计费设计（多轮工具调用会烧钱）

自由对话一次任务可能触发 3-5 次工具调用，token 消耗远高于单轮问答。必须分开计价：

| 场景 | 扣费 | 说明 |
|---|---|---|
| 纯概念问答 | 按量，封顶 5 积分 | 走 `preauth` + `settle` |
| 对话中触发回测 | **额外扣 10 积分/次** | 这是算力 + 核心价值，不能含在对话费里 |
| 对话中触发参数扫描 | 额外扣 20 积分/次 | 内部要跑 12 次回测 |
| 对话中触发部署 | 额外扣 5 积分/天 | 按部署日租走 |

**关键实现**：工具执行器返回结果时，同时返回这次工具该扣多少分，由路由层统一扣，不要让模型决定价格。

```python
TOOL_PRICE = {
    "run_backtest": 10,
    "compare_strategies": 20,     # 内部多次回测，按打包价
    "suggest_params": 20,
    "search_strategies": 0,        # 检索不收费，降低提问门槛
    "list_symbols": 0,
    "explain_concept": 0,
}
```

**检索类工具必须免费**，否则用户连"你有什么策略"都不敢问，转化漏斗在第一步就断了。

### 下一步只剩一件事：把工具循环接到 MiMo 上

`routers/ai.py`，核心就是一个 while 循环：

```python
while True:
    resp = call_mimo(messages, tools=TOOLS)
    if not resp.tool_calls:
        break                                  # 模型不再要工具，输出最终回答
    for call in resp.tool_calls:
        result = executor.execute(call.name, call.args)
        charge_for_tool(call.name)             # 按 TOOL_PRICE 扣费
        messages.append(tool_message(call.id, result.for_model()))
```

**这个循环就是整个产品的发动机**，其余都是外壳。

### 两条使用提醒

- `fetch_bars.py` 第一次跑用 `--full` 拉 5 年，之后每天跑一次增量即可。
  想先看会写什么再决定，加 `--dry-run`
- `fetch_bars.py` 里的 `ON DUPLICATE KEY UPDATE` 是 MySQL 语法，**这个脚本只在 MySQL 上跑**，
  不像 `credits.py` 那样兼容 SQLite。这是有意的：它是离线任务，不需要跨库
