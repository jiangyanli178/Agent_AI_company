🏗三层架构总览

系统采用 MiMo-OPC 三层架构：执行层负责专业分工执行，编排层负责全流程调度与闸门把控，中枢层负责数据留痕与人工决策。三条铁律贯穿始终：单一事实来源、不可逆动作过闸、全部留痕可回滚。

执行层 专职 Agent 团队
11 个 Agent 各司其职：数据收集师、策略翻译官、量化工程师、执行风险审计员、模型风险审计员、报告设计、评审 Agent、合规官、报价官、订单员、收银员。Agent 之间互不直接调用，全部经由 COO 调度。
编排层 COO Agent
全流程编排中枢。调度 9 步闭环：报价→建单→收款→数据采集→策略翻译→回测→风控审计→报告成稿→合规终检→交付回执。管理 3 轮审计否决升级机制与 3 轮评审打回机制。
中枢层 Context Hub + 闸门
9 个卷宗（00-charter ~ 08-review）作为单一事实来源；9 道人工闸门把控不可逆动作（定价、收款、发布、催款等）；07-log.md 全量动作留痕，支持 mark_stale 回滚。

🔬 研究执行链（数据 → 策略 → 回测 → 审计 → 报告）

📊 数据收集师 DataCollector
国内直连真实行情采集，四级降级链保障数据可得性；快照落盘可复现
核心方法

🧠 策略翻译官 StrategyTranslator
自然语言策略想法 → 结构化策略规格（StrategySpec），含完整解读与微调指引
核心方法
translate(idea) → StrategySpec
输出

  • interpretation 字典：clarity（明确/默认计数）/ items（原文线索→解读→确定性）/ params（参数→取值→来源→如何微调）/ assumptions（满仓、成本 0.1%/边、t+1、只做多）/ to_confirm（待确认项）

🔄COO 调度流程（run_first_order）

COO 持有全部 10 个下属 Agent 实例，按固定顺序调度。单股流程 9 步闭环：

1
开工 · 留痕
COO.log("开工")，记录订单参数
2
报价 → 闸门⑤
Quoter.quote 校验定价带（300~1000 ¥）→ GateKeeper.checkpoint(5) 价格与条款人工审批
3
建单 + 收款单 → 闸门⑥
OrderClerk.create_order → Cashier.generate_invoice → GateKeeper.checkpoint(6) 真实收付款（Agent 永不碰资金）
4
多股分支判断
parse_symbols(symbol)：单股→步骤 5 继续；多股→ _run_multi_research 分支
5
数据采集 + 策略翻译
DataCollector.collect（四级降级链）→ DataSnapshot；StrategyTranslator.translate → StrategySpec
6
回测 + 风控审计（≤3 轮）
QuantEngineer.build_and_run → 执行风险审计员 + 模型风险审计员 → merge_risk_audits 聚合；否决→定向打回量化工程师；3 轮仍否决→ AuditRejected 升级老板
7
报告成稿 + 评审循环（≤3 轮）
ReportDesigner.render → Reviewer.review（DoD 9 章 + 指标 + 审计非否决）；不过→旧稿 rename 版本留痕后重跑；3 轮不过→升级老板
8
合规终检（一票否决）
ComplianceOfficer.check：禁词扫描 + 免责声明/风险揭示 + 最大回撤揭示
9
QC + 交付回执 + 入账
metrics 五指标齐全 + 09-backtest 资产存在 → _book_order 幂等入账（orders.json + 06-finance.md）→ receipt → 05-pipeline.md 留痕

循环与升级机制

机制最大轮数打回对象超限处理
风控审计循环3 轮量化工程师（定向修改参数/逻辑）AuditRejected 升级老板，报告不出稿

🛡风控审计域（两大审计 Agent）

风控审计拆分为两个独立 Agent，各自产出完整而详细的结论（conclusion_md），由 merge_risk_audits() 聚合为下游兼容结构。

执行风险审计域 · ExecutionRiskAuditor

检查项判定标准实测指标
未来函数（数据泄漏） 红线 成交至少滞后信号 1 根K线（execution_lag ≥ 1）；组合版附加「日期交集对齐、不外推」 execution_lag / 对齐方式
参数敏感性 夏普极差 ≤ 1.5 且 正夏普参数组合占比 ≥ 60% sensitivity_spread / sensitivity_rows（fast±3 × slow±5 共 9 组网格）

模型风险审计域 · ModelRiskAuditor

检查项判定标准实测指标
过拟合（样本内外） 前 70% IS / 后 30% OOS：oos_sharpe ≥ 0.3 × is_sharpe 且 oos_total_return > -15% is_sharpe / oos_sharpe / oos_return
幸存者偏差 数据快照必须记录 pool_definition（股票池口径）非空 pool_definition

综合判定口径（_audit_verdict）

判定条件COO 后续动作
通过四项全部通过继续报告成稿
有条件通过恰好 1 项失败 且 失败项非「未来函数」继续报告成稿，附条件说明
否决未来函数失败，或 ≥2 项失败打回量化工程师，≤3 轮，超限升级老板

审计产出结构

# 单域审计 dict
{
  "agent": "执行风险审计员" | "模型风险审计员",
  "scope": "未来函数 / 参数敏感性" | "过拟合 / 幸存者偏差",
  "verdict": "通过" | "有条件通过" | "否决",
  "checks": [{"item", "passed", "detail"}, ...],
  "data": {"execution_lag", "sensitivity_spread", ...},
  "conclusion_md": "完整详细结论（判定标准/实测/判定/风险含义/微调建议）"
}

# merge_risk_audits 聚合结构
{
  "verdict": "通过" | "有条件通过" | "否决",   # 四项重判
  "checks": [...],           # 固定顺序：未来函数→过拟合→参数敏感性→幸存者偏差
  "is_sharpe", "oos_sharpe", "sensitivity_spread",
  "execution": {...},        # 执行风险完整结论
  "model": {...},            # 模型风险完整结论
  "per_stock": {...}         # 组合版附加分股明细
}

🗄Context Hub 中枢与留痕机制

Context Hub 是单一事实来源：9 个卷宗 + 回测资产库 + 订单台账 + 全量日志。所有 Agent 只读写 Context Hub，全部动作留痕可回滚。

卷宗内容

02-brand.md命名、VI、语调、金融广告禁词表

06-finance.md票据、收支、毛利、现金流（_book_order 入账留痕）

关键机制

  • 版本留痕：write(name, content, versioned=True) 旧稿 rename 为 *.v{n}.md 顺延
  • 回滚机制：mark_stale(name) → 07-log.md 记 [STALE] + 文件 rename 为 *.stale.*
  • 幂等入账：_book_order 先剔除同 order_id 旧记录再 append，绝不重复入账
  • 日志格式：## 时间 | Agent | 动作 + 输入/输出/工具调用/截图索引

📈多股组合回测

当标的为多只股票时，COO 转入 _run_multi_research 分支：每股独立闭环 + 等权组合闭环，产出 N+1 份报告。

分支流程

1
策略翻译一次（全标的共用）
StrategyTranslator.translate(idea) → 同一 StrategySpec 应用于所有标的
2
每股独立闭环（N 份个股报告）
collect → build_and_run → 风控审计 ≤3 轮 → 报告成稿 → 评审 ≤3 轮 → 合规终检；每股独立子目录 09-backtest/<order_id>/<safe>/
3
等权组合闭环（1 份组合报告）
日期交集对齐（≥60 天）→ 等权按日再平衡 → run_portfolio_backtest → 组合审计（含 per_stock 明细）→ portfolio_report.md
4
组合 QC + 入账
每股 strategy_spec.json + reproduce.py 齐备 + 组合 portfolio_strategy_spec.json + reproduce_portfolio.py + 五指标齐全

组合回测口径

  • 日期对齐：日期交集保序，不足 MIN_ALIGNED_DAYS=60 抛 ValueError，绝不外推缺失日
  • 等权再平衡：组合日收益 = 各股策略日收益等权平均（按日再平衡简化口径）
  • 指标携带：per_stock（对齐窗口口径分股明细）、weighting、aligned_days
