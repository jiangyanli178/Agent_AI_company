# 部署方案与影响评估
## 没有云服务器 + 用内网穿透，到底影响什么

---

## 一、没有云服务器和域名，影响有多大

### 1.1 对评分的影响

| 维度 | 官方要求 | 影响 |
|---|---|---|
| 完成度 25 分 | 「产品是否可访问」 | **有影响，但可缓解**。内网穿透给出的也是公网 URL，评委手机能打开就算可访问 |
| 商业化 25 分 | 获客与真实交易 | **基本无影响**。第一单照样能收，收款码不依赖域名 |
| 创新性 35 分 | 公司形态与闭环 | **无影响** |

**结论**：缺云服务器不是致命的，**只要有一个能打开的公网链接**。
真正会扣分的是"只能在自己电脑上演示，评委打不开"。

### 1.2 三个真实存在的影响

| 影响 | 严重度 | 说明 |
|---|---|---|
| **演示结束后链接失效** | 中 | 评委如果想会后再看一遍，你电脑关了就没了 |
| **没有 HTTPS 证书** | 低 | 穿透工具一般都自带 HTTPS，实际影响很小 |
| **现场稳定性全在你笔记本上** | **高** | 合盖、断网、休眠、死机，演示当场崩 |

第三条才是重点。**准备再充分，也抵不过演示时笔记本自动休眠。**

### 1.3 必须做的三个设置（演示当天）

```powershell
# Windows：接通电源、禁止休眠
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /change monitor-timeout-ac 0
```

- 插着电源演示
- 关闭 VPN（很多 VPN 会干扰穿透隧道）
- 提前 30 分钟启动服务，不要临上台才开

## 二、内网穿透的真实影响

### 2.1 最大的坑：免费版域名会变

| 工具 | 免费版域名 | 影响 |
|---|---|---|
| cpolar | **每次重启随机换** | 印在 PPT 和二维码上的链接，重启就作废 |
| natapp | 免费版同样不固定 | 同上 |
| ngrok | 免费版随机 | 同上 |

**这是最容易踩的坑**：你前一天把二维码印好，第二天重启电脑，全部失效。

**解决办法（按推荐排序）**：

1. **花十几块买固定域名**。cpolar 固定二级域名约 10-20 元/月，这是最省心的办法
2. **演示当天只启动一次，中途绝不重启**，二维码现场生成投屏
3. **二维码现场生成**，不要提前印。用手机扫一扫现场投屏的码，规避一切变化

### 2.2 稳定性与速度

- 免费版通常限速 1Mbps 左右，**回测曲线、对话这类小数据量完全够用**
- AI 流式输出可能略慢，但反而更像"在思考"，不算坏事
- 穿透服务本身可能抖动，**必须有兜底方案**

**兜底方案（必须准备）**：
1. 提前录好 3 分钟演示视频，真崩了就放视频
2. 手机开热点备用，防止现场 Wi-Fi  congested
3. 关键页面提前截图，放进 PPT

### 2.3 安全风险（这条最容易被忽略）

把本地服务暴露到公网，意味着**互联网上任何人都能访问**。

| 绝对不能暴露 | 原因 |
|---|---|
| MySQL 3306 | root/root 弱密码，等于把数据库送给别人 |
| phpMyAdmin / 任何数据库管理界面 | 同上 |
| `.env` 文件路径 | 里面有 MiMo key |
| 后端 `/docs` | 会暴露全部接口结构，生产环境建议关掉 |

**只暴露该暴露的**：
- 前端页面（打包后的静态文件）
- 后端 `/api/*`

**必须有的防护**：
- `/api/admin/*` 已经做了 `require_admin` 校验 ✅
- 生产环境把 FastAPI 的 `docs_url` 关掉
- 数据库只监听 `127.0.0.1`，不要监听 `0.0.0.0`

检查 MySQL 是否只监听本地：
```sql
SHOW VARIABLES LIKE 'bind_address';    -- 应该是 127.0.0.1 或空
SELECT user, host FROM mysql.user;     -- root 的 host 应该是 localhost，不能是 %
```

**如果 `root` 的 host 是 `%`，必须先改掉再穿透**，否则你的数据库就是公开的。

### 本机实测结果（2026-11-06）

```
bind_address = *                    ← 监听所有网卡
root@localhost                      ← 但 root 只允许本地连接
其余账号均为 mysql.*@localhost      ← 系统账号，外部无法登录
```

**结论：当前配置下穿透是安全的**，因为即使端口对外可达，
外部也无法用任何账号通过认证。

**建议**（不紧急）：把 `bind_address` 改成 `127.0.0.1`，多一层保险。
上线前**必须**改掉 root/root 弱密码，并新建一个只有 `quant_shop` 库权限的专用账号：

```sql
CREATE USER 'quant'@'localhost' IDENTIFIED BY '一个足够长的随机密码';
GRANT SELECT, INSERT, UPDATE, DELETE ON quant_shop.* TO 'quant'@'localhost';
FLUSH PRIVILEGES;
```

注意：应用只需要增删改查，**不要给 DROP、TRUNCATE、GRANT 权限**。

### 2.4 合规问题

比赛演示性质不属于经营行为，**不需要备案**。
但如果赛后继续对外提供服务并收费，就需要正规备案了。

## 三、三个方案对比与我的建议

| 方案 | 成本 | 时间 | 稳定性 | 适合 |
|---|---|---|---|---|
| 云服务器 + 域名备案 | 100-300 元 | **1-3 周** | 高 | 长期运营，**本次来不及** |
| **内网穿透（免费）** | 0 | 10 分钟 | 中 | 本次演示，**推荐** |
| 内网穿透（固定域名） | 约 20 元 | 15 分钟 | 中高 | **最推荐**，省去域名变化的麻烦 |

### 我的建议

**用内网穿透，但花 20 元买固定域名。** 理由是：

- 你要在 PPT、卷宗、二维码里写链接，域名变了全部要重印
- 20 元相比你投入的 24 小时，可以忽略
- 演示当天少一个变量，就少一分紧张

**如果实在不想花钱**：免费版 + 二维码现场生成投屏 + 演示当天不重启。

## 四、演示当天的检查清单

```
□ 笔记本插电源，休眠已关闭
□ VPN 已关闭
□ 穿透隧道已启动 30 分钟以上，且没有重启过
□ 用手机（非电脑）扫二维码，确认能打开
□ 用 4G/5G 而不是现场 Wi-Fi 再测一次
□ 数据库确认没有暴露公网
□ /api/admin 需要登录才能访问
□ 收款码能正常扫出
□ 3 分钟演示视频已录好（兜底）
□ 关键页面截图已放进 PPT（兜底）
□ 手机热点已测试可用（兜底）
```

**最后三条是保险**，希望你用不上，但必须准备。
